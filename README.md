# 原神四星抽卡概率计算器（马尔可夫链精确解）

用 Python 标准库实现的**四星**抽卡概率计算器，覆盖**角色池**与**武器池**。
不依赖 numpy / scipy，一个文件直接跑。

核心思路：把每个卡池建模成一条马尔可夫链，状态为

```
(四星保底计数 pity, 四星大保底标记 guarantee, UP物品1已获得数, …, UP物品n已获得数)
```

其中 n = 角色池 3、武器池 5（状态是变长的，两个池子各按自己的 UP 个数建模）。

逐抽推进状态分布，就能得到**精确**（非模拟）的概率；再按「优先池」顺序把两个池子
用卷积组合起来，得到整个抽卡计划的成功率。

能输出的东西：

* **当前抽数下达成整个计划的成功率**；
* **成功率随抽数变化的函数** `P(N)`（文本柱状表 / CSV / SVG 折线图 / JSON 数组）；
* 「想有 10%/25%/30%/50%/75%/80%/90%/95%/99% 把握，各需要多少抽」
  以及「再多抽 10/20/30/50 抽能涨多少」；
* **花光全部抽数后的结果分布**：最可能出现的几种结果排在最前面（文本表 / CSV / SVG 柱状图），
  以及「还差 1 个 / 2 个 …… 目标物品」的缺口分布；
* 每个池子的完成率、每个 UP 物品的达成概率与期望获得数。

> 卡池构成：**角色池有 3 个 UP 角色，武器池有 5 个 UP 武器**；
> 中 UP 时在池内等概率随机（角色 1/3、武器 1/5）。
> 命令行里 `--char-targets` 接 3 个数、`--weapon-targets` 接 5 个数。

## 1. 模型与假设

### 1.1 四星概率表（第 n 抽出四星）

| 抽数 | 角色池 | 武器池 |
| --- | --- | --- |
| 第 1~7 抽 | 5.1% | 6.0% |
| 第 8 抽 | 5.1% | **66.0%** |
| 第 9 抽 | **56.1%** | 126.0% |
| 第 10 抽 | 107.1% | — |

**两个池子的保底档数不一样**：

* 角色池：前 8 抽 5.1%，第 9 抽 56.1%，第 10 抽 107.1% → **第 10 抽必出**，垫抽范围 0~9；
* 武器池：前 7 抽 6.0%，第 8 抽 66.0%，第 9 抽 126.0% → **第 9 抽必出**，垫抽范围 0~8。

大于 100% 的值在程序里按 **100%（必出）** 处理。第 `pity+1` 抽的概率查表，
出四星后计数归零，没出则 +1，所以 pity 永远不会越过最后一档。

由这两张表推出的四星平均间隔（从刚出过四星开始算）：

* 角色池：**7.655 抽 / 个四星**
* 武器池：**6.728 抽 / 个四星**（软保底来得更早，所以比角色池更密）

### 1.2 UP 判定（四星大保底）

* 没处于大保底时出四星：按 `up_rate`「不歪」——**角色池 50%、武器池 75%**；
  歪了就进入大保底；
* 处于大保底时出四星：**100%** 是 UP，命中后解除大保底；
* 命中 UP 时，在该池的 UP 物品里**等概率**随机取一个：

  | 卡池 | UP 个数 | 不歪概率 | 非大保底时命中指定某个 UP | 大保底时命中指定某个 UP |
  | --- | --- | --- | --- | --- |
  | 角色池 | 3 个 UP 角色 | 50% | 50% ÷ 3 ≈ 16.67% | 1/3 ≈ 33.33% |
  | 武器池 | **5 个 UP 武器** | **75%** | 75% ÷ 5 = 15% | 1/5 = 20% |

### 1.3 抽卡顺序（优先池）

「先武器池」= 一直抽武器池，直到**武器池的计划全部达成**（或抽数用尽），再切到角色池。
反过来同理。抽数用尽时计划未完成即算失败。

### 1.4 不在模型内的东西（重要）

* **不包含五星**：没有五星概率、没有五星保底、没有武器池命定值（定轨）、
  也没有「五星与四星互相挤占」的星级冲突。本模型只回答「四星/四星 UP 够不够」。
* 同一池内的 UP 物品彼此等概率，且抽到 UP 时的选择完全随机
  （不区分「更想要哪一个」的优先级）。

## 2. 数学原理

### 2.1 马尔可夫链

状态空间大小 = `2 × 保底档数 × Π(tᵢ+1)`，其中 `2` = 是否大保底，
保底档数 = 角色池 10 / 武器池 9，`tᵢ` 是第 i 个 UP 物品的目标数量
（计数在目标处**饱和**，多抽的不影响结果）；角色池 i 取 1~3，武器池 i 取 1~5。
例如武器池 5 个目标都是 1 时只有 `2 × 9 × 2⁵ = 576` 格。

单抽转移（分布用 `dist[pity][guarantee][c₁]…[c_n]` 表示，`n` = 该池的 UP 个数）：

| 情形 | 概率 | 新状态 |
| --- | --- | --- |
| 没出四星 | 1 − q(pity) | `pity+1`，其余不变 |
| 出四星且命中某个 UP | q(pity) × up_rate × 1/n | `pity=0`，大保底=否，该计数 +1（饱和） |
| 出四星但歪了（仅无大保底时） | q(pity) × (1 − up_rate) | `pity=0`，大保底=是 |
| 出四星（大保底时必 UP） | q(pity) × 100% × 1/n | `pity=0`，大保底=否，该计数 +1（饱和） |

其中 `q(pity) = min(1, 概率表[pity])`，`n` = 角色池 3、武器池 5，
`up_rate` = 角色池 0.50、武器池 0.75，概率表长度 = 角色池 10 / 武器池 9
（最后一档概率 >100%，即必出）。

记 `F(k)` = 到第 k 抽为止「该池计划全部达成」的概率（即目标格子的概率质量）。
`F` 单调不减，`F(k) − F(k−1)` 就是**首次达标恰好发生在第 k 抽**的概率。

### 2.2 两个池子的组合

两池的四星保底、大保底完全独立（各自的计数器）。设角色池单独抽完需要 T_c 抽，
武器池单独抽完需要 T_w 抽，则「先角色后武器」的总消耗是 `T_c + T_w`，
「先武器后角色」的总消耗还是 `T_c + T_w`。于是：

```
P(全部完成) = P(T_c + T_w ≤ N)
            = Σ_k P(T_c = k) · F_w(N − k)      ← 先角色后武器的写法
            = Σ_k P(T_w = k) · F_c(N − k)      ← 先武器后角色的写法
```

**结论：在这个模型下，全部计划的完成概率与平均消耗抽数与「先抽哪个池子」无关**
（两者是同一个卷积的两种展开）。顺序真正影响的是**预算不足时先保住哪个池子**，
以及每个具体 UP 物品的达成概率。程序会同时给出两种顺序的分池完成率和物品达成率。

> 注意 `T_w` 是「武器池的**全部**目标都达成」所需抽数。武器池虽然有 5 个 UP 武器，
> 但它不歪概率更高（75%），所以单次要某一把武器是 `75% ÷ 5 = 15%`，
> 跟角色池的 `50% ÷ 3 ≈ 16.67%` 很接近。

平均消耗抽数用 `E[min(T, m)] = Σ_{j<m} P(T > j) = Σ_{j<m} (1 − F(j))` 计算。

### 2.3 成功率随抽数变化的函数

把上式里的 N 当成自变量，得到的就是程序输出的那条曲线：

```
P(N) = P(T_c + T_w ≤ N),   N = 0, 1, 2, ...
```

也就是「总消耗 T = T_c + T_w 的累积分布函数」。它是单调不减的，
`P(当前抽数)` 就是报告最上面那个数字；曲线本身由 `solve(plan, max_pulls=...)`
一次算出（`P(N)` 逐个 N 用 C 级 `sum(map(mul, ...))` 做卷积，2000 抽以内是毫秒级）。

反过来的问题「想有 p 的把握需要多少抽」= 求 `P(N) ≥ p` 的最小 N，
就是程序里的 `curve.needed_for(p)` / 报告里的「达成把握与所需抽数」。

### 2.4 花光抽数后的结果分布

设优先池单独抽完需要 T₁ 抽，预算为 N，另一个池子拿到剩下的抽数，则最终结果只有两种情形：

```
情形 A（概率 F₁(N)）：T₁ = k ≤ N   ->  优先池数量 = 满目标（数量在目标处饱和）
                                        另一池 = 「N − k 抽后的数量分布」按 P(T₁ = k) 加权混合
情形 B（概率 1−F₁(N)）：T₁ > N      ->  优先池 = N 抽后的数量分布（去掉已完成的那部分质量）
                                        另一池 = 一抽没抽，数量全为 0
```

两种情形在「优先池数量」这一维上互斥、并且合起来概率为 1，所以

```
P(优先池 = a, 另一池 = b) = [a = 满目标] · Σ_k P(T₁ = k)·Q_{N−k}(b)  +  [b = 全 0] · R_N(a)
```

就是一个合法的联合分布（`Q_m` = 另一池抽 m 抽的数量分布，`R_N` = 优先池 N 抽后未完成的部分）。
程序把它按概率从高到低排序输出，并顺带给出缺口分布 `P(还差 g 个目标物品)`；
它的边缘分布与前面算的「各 UP 达成概率 / 期望获得数」完全一致（测试里有交叉验证），
「缺口 = 0」那一项的概率就等于总成功率。

注意：**结果分布与抽卡顺序有关**（优先池拿满目标的机会更大），
而总成功率与顺序无关（见 2.2）——报告里两者都会给出。

## 3. 使用方法

### 3.1 命令行

```powershell
python genshin_4star_calculator.py `
    --order weapon `
    --pulls 90 `
    --char-pity 2 --char-guarantee `
    --weapon-pity 0 --no-weapon-guarantee `
    --char-targets 2 0 0 `
    --weapon-targets 1 1 0 0 0
```

参数表：

| 参数 | 含义 |
| --- | --- |
| `--order {c,w,character-first,weapon-first}` | 抽卡顺序（优先哪个池子），默认先角色池 |
| `-p/--pulls N` | 当前可用抽数 |
| `--char-pity N` / `--weapon-pity N` | 角色池 / 武器池已垫的抽数（角色 0~9、武器 0~8，四星保底计数） |
| `--char-guarantee` / `--weapon-guarantee` | 该池处于四星大保底（默认否） |
| `-ct/--char-targets N1 N2 N3` | UP角色1/2/3 各想要几个 |
| `-wt/--weapon-targets N1 N2 N3 N4 N5` | UP武器1~5 各想要几个 |
| `--json` | 输出 JSON（便于脚本/其他程序调用） |
| `--curve [MAX]` | 打印「成功率随抽数变化」表，最多算到 MAX 抽（省略 MAX 时自动取 `当前抽数 + max(60, 当前抽数/2)`） |
| `--csv PATH` | 把成功率曲线导出成 CSV（utf-8-sig，Excel 直接打开不乱码） |
| `--svg PATH` | 把成功率曲线导出成 SVG 折线图（不需要 matplotlib） |
| `--dist [K]` | 打印「花光抽数后的结果分布」表，按概率从高到低显示前 K 种（默认 12） |
| `--dist-csv PATH` | 把完整结果分布导出为 CSV（含每个结果的概率、累计概率、缺口） |
| `--dist-svg PATH` | 把结果分布导出为 SVG 横向柱状图（最可能的结果在最上面） |
| `--no-dist` | 不计算/不打印结果分布（略快） |
| `--no-curve` | 不把曲线算到当前抽数之外（更快）；若同时给了 `--curve MAX`，以 MAX 为准 |
| `--verify [次数]` | 额外跑蒙特卡洛模拟与精确解对照（默认 20000 次） |
| `--seed N` | 蒙特卡洛随机种子 |

只想算一个池子时，把另一个池子的目标全写成 0（角色 `0 0 0`、武器 `0 0 0 0 0`）即可。

### 3.2 交互式

```powershell
python genshin_4star_calculator.py -i
```

不传 `--pulls` 且在终端里直接运行脚本时，也会自动进入交互式提问。

### 3.5 作为库调用

```python
import genshin_4star_calculator as G

plan = G.Plan(
    order="weapon-first", pulls=90,
    char_pity=2, char_guarantee=True,
    weapon_pity=0, weapon_guarantee=False,
    char_targets=(2, 0, 0),          # 角色池 3 个 UP 目标
    weapon_targets=(1, 1, 0, 0, 0),  # 武器池 5 个 UP 目标
)
result = G.solve(plan, max_pulls=200, want_distribution=True)   # max_pulls = 曲线算到多远

print(result.chosen.success)                      # 当前 90 抽的成功率 = 0.3033
print(result.success_at_current_pulls)            # 同上
print(result.curve.prob[120])                     # 给 120 抽时的成功率 = 0.5287
print(result.curve.at(120))                       # 同上（带范围检查）
print(result.curve.needed_for(0.80))              # 想有 80% 把握需要多少抽 -> 171
print(result.curve.gains(90))                     # [(10, 0.2801), (20, ...), ...]
print(result.curve.as_pairs()[:3])                # [(0, 0.0), (1, 0.0), (2, 0.0)]
print(result.chosen.item_prob)                    # 各 UP 物品达成概率（角色 3 个 + 武器 5 个）
print(result.curves["character"].complete[50])    # 角色池 50 抽内完成概率

dist = result.distribution                        # 花光 90 抽后的结果分布
print(dist.success)                               # 全部达成的概率（= result.chosen.success）
print(dist.total_outcomes)                        # 可能出现的结果种数
for char_counts, weapon_counts, p in dist.top(3): # 最可能的 3 种结果
    print(char_counts, weapon_counts, f"{p:.2%}")
print(dist.gap_probs)                             # P(还差 0/1/2/... 个目标物品)
print(dist.expected_gap)                          # 平均还差几个
print(dist.item_marginal("weapon", 0))            # UP武器1 达标的概率

G.write_csv_curve(result.curve, "曲线.csv", plan.pulls)     # 导出成功率曲线 CSV
G.write_svg_curve(result.curve, "曲线.svg", plan.pulls)     # 导出成功率曲线 SVG
G.write_csv_outcome(dist, "结果分布.csv")                   # 导出结果分布 CSV
G.write_svg_outcome(dist, "结果分布.svg", top_k=10)         # 导出结果分布 SVG 柱状图

# 单池直接玩马尔可夫链（注意目标个数要和池子的 UP 个数一致）
chain = G.FourStarChain(G.CHARACTER, (2, 1, 0), start_pity=4, start_guarantee=True)
for _ in range(30):
    chain.step()
print(chain.complete_prob(), chain.item_reached_probs())

chain = G.FourStarChain(G.WEAPON, (1, 0, 1, 0, 0), start_pity=9, start_guarantee=True)
chain.step()
print(chain.item_reached_probs())   # 垫满 9 抽 + 大保底：必出四星且必为 UP，5 选 1
```

> 注意 `plan.pulls` 是**当前预算**（决定报告中「当前抽数成功率」），
> `solve(..., max_pulls=...)` 只决定**曲线算多远**，两者互不影响。

## 4. 输出解读

以 `--order weapon --pulls 90 --char-pity 2 --char-guarantee --char-targets 2 0 0 --weapon-targets 1 1 0 0 0` 为例：

```
【总体结论】
  当前抽数 90 抽的成功率   : 38.29%   （把两池计划全部完成）
  平均消耗抽数            : 81.07 / 90（平均剩余 8.93 抽）

【分池完成率】
  池子            单独给满90抽  先武器池，后角色池  先角色池，后武器池
  角色池                78.75%              30.33%              78.75%
  武器池                79.66%              79.66%              30.33%

【各 UP 物品达成概率】
  物品          目标  先武器池，后角色池  先角色池，后武器池   期望获得*
  UP角色1          2              30.33%              78.75%        0.87
  UP武器1          1              89.49%              46.60%        0.89
  UP武器2          1              89.49%              46.60%        0.89
```

* **当前抽数成功率**：就是曲线上的那一点 `P(plan.pulls)`。
* **单独给满 90 抽**：只考虑这一个池子、把全部抽数都给它时的完成概率。
* **某顺序下的分池完成率**：先抽的池子拿满全部预算，后抽的池子只能吃剩下的；
  所以「先武器池」时武器池 79.66%、角色池被挤到 30.33%。
* **期望获得**：`E[min(获得数量, 目标)]`，在目标数量处封顶，按当前顺序计算。
* 结果里 `--verify` 会附一张对照表，蒙特卡洛与精确解的差值通常在千分之一量级。

## 5. 正确性验证

```powershell
python test_genshin_4star_calculator.py     # 71 个测试
```

测试分七类：

1. **解析值校验**：例如「垫 0 抽时角色池前 8 抽都不出四星的概率 = 0.949⁸」、
   「武器池前 7 抽都不出 = 0.94⁷，第 8 抽还没出 = 0.94⁷ × 0.34」、
   「垫满最后一档且大保底时第一抽 1/3（角色）/ 1/5（武器）命中某个 UP」、
   「0.5/3 + 0.5×0.051/3 + 0.5×(2/3)×0.051×(0.5/3) = 0.178」等手算值。
2. **UP 个数 / 保底档数 / 不歪概率**：角色池 3 个 UP、10 档保底、不歪 50%；
   武器池 5 个 UP、**9 档保底、不歪 75%**；目标个数或垫抽数越界都会报错；
   单次命中某把 UP 武器的解析概率 6%×75%÷5 = 0.9%、大保底时 20%；
   两个池子的四星平均间隔（7.655 / 6.728 抽）与 4 万次模拟一致。
3. **结构性质**：概率在 [0,1]、完成率单调不减、`Σ 首次达标分布 = F(N)`、
   目标为 0 时不消耗抽数、更多抽数不会让成功率变差。
4. **成功率曲线**：与「逐点独立卷积」的结果一致、`P(当前抽数)` 等于报告里的成功率、
   单调不减、把曲线算得更远不会改变当前抽数处的结论（短曲线是长曲线的前缀）、
   `needed_for` 返回第一个达到该把握的抽数。
5. **结果分布**：总概率为 1、按概率降序且并列时更好的结果在前、
   「缺口 = 0」的概率等于总成功率、边缘分布与「各 UP 达成概率 / 期望获得数」逐项一致、
   平均缺口 = 目标总数 − 期望获得总数、数量不超过目标、两种顺序的分布不同但成功率相同。
6. **蒙特卡洛对照**：模拟器是与马尔可夫链完全独立的另一套实现，
   用 2~3 万次模拟对照总成功率、平均消耗、各物品达成率、**以及概率最高的 5 种结果**（4σ 容差）。
7. **界面冒烟**：命令行、JSON、`--curve`、`--dist`、`--csv`/`--svg`/`--dist-csv`/`--dist-svg`
   （含 XML 良构校验）、`--verify`、交互式输入、错误提示。

性能：常见输入（目标 1~2 个、抽数 ≤ 200）在 0.3 秒内；
8 个 UP 全要 2 个、300 抽约 0.9 秒。结果分布是「顺手」算出来的
（在原有的马尔可夫链推进里顺带累积，不额外跑一遍动态规划），开销约 5%；
曲线算得越远耗时线性增加，用 `--no-curve` 可以只算到当前抽数。
武器池 5 个 UP 会让状态空间变成 `Π(tᵢ+1)`，目标个数较大时会明显变慢，
程序会在开工前给出提示。
